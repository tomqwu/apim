# MuleSoft current-state baseline

MuleSoft must be scored from organization-specific inventory and operations evidence, not generic platform documentation. API Manager policies address gateway controls, while Mule runtime applications may include DataWeave transformations, flows, connectors, schedules, queues, and business logic.

## Baseline measures

- APIs/apps/flows/connectors/policies by environment and owner.
- Transactions, payloads, latency, failures, incident burden, deployment frequency, and recovery time.
- Runtime versions, end-of-support, infrastructure, licenses, support, and staff/partner cost.
- Reusable assets and coupled dependencies.
- DataWeave and orchestration complexity; state, retries, idempotency, and reconciliation.
- Contract, consumer, certificate, network, and audit dependencies.

The baseline is the cost/risk/function to beat. A migration that reduces license cost but increases outage risk or hidden custom integration is not success.
