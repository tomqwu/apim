# Kong vendor validation questions

1. Propose exact Konnect hybrid and self-managed bills of material, versions, editions, and licenses for the organization-specific scenarios.
2. Identify every configuration, metadata, credential, analytics, and support-data category crossing the CP/DP boundary and its storage region/retention.
3. Demonstrate existing DP traffic, pod restart, clean scale-out, config update, telemetry, and recovery through a prolonged CP interruption.
4. Provide the topology/edition matrix for OIDC, JWT, mTLS, request/OAS validation, rate limiting, portal, analytics, secrets, and audit.
5. Explain the documented OAuth 2.0 plugin hybrid limitation and recommended Entra client-credentials architecture.
6. Compare local, Redis, and Advanced rate-limit strategies under replica/region and Redis failure.
7. Define KIC versus Kong Operator roadmap, support, Gateway API conformance, upgrade, and ownership boundaries.
8. Demonstrate CP/DP certificate rotation and revocation without request-path interruption.
9. Explain version-skew, emergency security patch, rollback, and support-window policy.
10. Show how to prevent decK, KIC, Terraform, UI, and API processes from becoming conflicting writers.
11. Demonstrate audit export, configuration export/restore, Konnect exit, and entitlement-loss behavior.
12. Provide regional data-residency, subprocessor, support-access, and data-deletion commitments.
13. Define support responsibility for AKS, CNI, NetworkPolicy, mesh, Redis, Prometheus, OpenTelemetry, and custom plugins.
14. Provide sizing methodology and a representative load-test plan rather than maximum-throughput marketing data.
15. State the conditions under which Kong would advise the organization to select APIM or Apigee instead.
