# Apigee vendor validation questions

1. Propose exact Apigee X and Hybrid variants, supported AKS/Kubernetes versions, regions, editions, and licenses.
2. Identify every data category exchanged with or stored in Google's management and analytics services.
3. Demonstrate Hybrid runtime traffic, restart, configuration, analytics, and reconciliation during management-plane loss.
4. Quantify runtime CPU/memory/storage and operations for message processors, synchronizer, Cassandra, MART, ingress, and telemetry.
5. Demonstrate installation, upgrade, backup, restore, version-skew, and rollback on the proposed supported platform.
6. Explain the runtime support window and how the organization avoids forced upgrades colliding with Kubernetes release cadence.
7. Demonstrate Entra/OIDC, mTLS, PKI rotation, secret manager, SIEM, and OpenTelemetry integration.
8. Define network egress, private connectivity, Google service, DNS, proxy, and certificate dependencies.
9. Demonstrate API product, application, credential, portal, delegated governance, and lifecycle journeys that differentiate Apigee.
10. Define support responsibility for Kubernetes, service mesh, Cassandra, network plugins, storage, capacity, and disaster recovery.
11. Demonstrate configuration/product/developer/app/credential/analytics export and vendor exit.
12. Provide regional data-residency, subprocessor, privileged-support, retention, deletion, and audit commitments.
13. Demonstrate multi-region runtime failover and data consistency without overstating management-plane independence.
14. Provide full TCO including runtime infrastructure, platform staffing, upgrades, nonproduction, DR, network, and Google services.
15. State the conditions under which Google would advise the organization to select Kong or APIM instead.
